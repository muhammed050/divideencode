You are a **Data Compression Research Engineer, Algorithm Designer, and Systems Programmer**.

Your mission is to investigate and experimentally develop a **new lossless data compression algorithm** inspired by the following idea:

> Files are ultimately represented as binary data (0s and 1s). Instead of simply applying conventional compression techniques, investigate whether mathematical transformations such as repeated division, numerical re-encoding, pattern extraction, and reversible transformations can create a more efficient representation.

The initial concept is:

If a value or sequence can be repeatedly divided by a number such as `2`, perhaps the resulting representation can be stored more efficiently, and during decompression the inverse operation can reconstruct the original data.

**Do NOT assume this idea works. Prove or disprove it experimentally.**

---

## 1. Analyze the Mathematical Idea

First, mathematically analyze:

* Why repeatedly dividing by `2` does not automatically create compression.
* What information is lost during division and rounding.
* How reversible transformations can preserve information.
* What conditions are required for a transformation to be perfectly reversible.
* Whether the concept can be converted into a real lossless encoding scheme.

Clearly distinguish between:

**Transformation**

and

**Compression**

Reducing the numerical value of something is NOT compression unless the total number of bits required to represent the complete information is actually reduced.

Create a prototype algorithm with the temporary name:

**DivideEncode**

**100% Lossless**

```text

   ↓

   ↓
```


```text

```

# 4. Investigate the Division Concept

Experiment with transformations based on:

```text
x / 2
x / 3
x / 4
x / 8
x / 16
```

and reversible mathematical representations.

Do NOT simply round values and discard the remainder.

Investigate whether the remainder can be encoded more efficiently.

For example, explore representations such as:

```text
x = q × d + r
```

where:

```text
q = quotient
r = remainder
```

Then investigate whether:

```text
q + r
```

can sometimes require fewer total bits than the original representation.

Also investigate whether the quotient/remainder structure exposes patterns that ordinary byte-level compression does not exploit.

The algorithm should search for:

* Repeated bytes
* Repeated bit sequences
* Repeated substrings
* Repeated numerical sequences
* Repeated differences
* Repeated structures
* Similar values
* Long runs
* Mathematical relationships

Example:

```text

```


But the representation must include enough information to reconstruct the original data exactly.

# 6. Adaptive Compression

Do not force one compression strategy on every file.

Create an adaptive system capable of choosing between multiple encoding strategies.

For example:

```text
RAW
RLE
DICTIONARY
DELTA
PATTERN
DIVIDE
BIT-PACK
HYBRID
```

The compressor should estimate the final encoded size of each strategy, including metadata, and choose the smallest result.

If compression makes the file larger, store the data using a RAW mode.

# 7. Recursive Compression Experiment

Investigate whether the compressed representation can itself be compressed further.

Test:

```text
Compress(data)
Compress(compressed_data)
Compress(compressed_data_2)
...
```

Stop automatically when another compression pass no longer decreases the total size.

However:

**Every header, dictionary, metadata structure, and control byte must be included when calculating the final size.**

Do not claim compression based on the payload alone.

# 17. Important Rule

Never confuse:

```text
smaller number
```

with:

```text
fewer bits
```

The only thing that matters for compression is the **total number of bits required to represent all information necessary to reconstruct the original data**.

Metadata counts.

Headers count.

Dictionaries count.

Indexes count.

Remainders count.

Flags count.

Everything counts.
